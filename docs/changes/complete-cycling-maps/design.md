## Context

骑行首页的目的地目录、导航画面与轨迹数据来自网页脚本中的演示值。骑士 iOS 已用高德搜索识别自提门店，再由骑行 SDK 算路，且已在 iPhone 和蓝牙测试接收器核对同一条真实转向。现有车载 OLED 为 128×64，支持两行状态。订单后台尚无车队定位数据。

## Goals / Non-Goals

**Goals** 统一普通骑行和自提算路，提供真实位置的自由骑行、历史轨迹与打卡地图，并让车载屏跟随手机的真实导航状态。

**Non-Goals** 独立网页演示、车载屏完整高德底图、订单或付款流程改动，以及车队位置共享。

## Decisions

1. 骑士以高德 POI ID 和坐标选择目的地。同名搜索结果展示区县和地址，由用户选定。美团自提继续校验门店名与已知地址。复用单一骑行会话，用户核对路线后开始导航。实时路线只由高德成功算路与导航回调生成。 [高德地点搜索](https://lbs.amap.com/api/maps-sdk-for-ios/guide/map-data/poi) · [高德骑行路线](https://lbs.amap.com/api/ios-navi-sdk/guide/route-plan/ride-route-plan)
2. 自由骑行在明确开始后按授权记录位置。定位质量不足或权限中断时暂停采集，并把轨迹分段。地图使用已转换的坐标绘制轨迹。个人记录存于手机，由用户查看与删除。历史演示项标明其来源，没有坐标的旧记录可保留文字。
3. 打卡以用户选择的真实地图点为目标。状态只有在成功取得合法位置且用户确认打卡时更新。地图图钉使用该地点的真实位置。
4. 保留车队现有功能，车队实时位置延后。本次不收集或传输队友位置。
5. 车载屏使用现有 BLE 服务。由导航回调生成箭头、下一转向距离和简短状态，发送会话中的最新提示；重算、结束、到达或超时替换旧提示。固件断连时清空，重连后只恢复仍有效的一条。旧固件支持继续显示两行文字。
6. 定位授权、网络、SDK 配置、无匹配及蓝牙不可用均在对应地图页面显示状态。验证资料分别标记代码测试、iPhone 真机、蓝牙接收器和实体车载屏。

## Risks / Trade-offs

- 实体头显需通电并广播才能验收显示。蓝牙接收器可验证转向与距离传输。
- 轨迹只记录到真实定位点。读取精度不足时，地图提供定位状态并保留已经记录的有效路段。
