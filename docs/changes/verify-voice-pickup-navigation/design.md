## Context

外部高德交接调用 `iosamap://path`，当前代码只能核实打开了路线预览。骑士现有导航控制器在用户确认高德隐私与定位后，可以调用 `startGPSNavi`，并在 `didStartNavi` 的 GPS 模式回调后进入实际导航。现有小布工具先等蓝牙或服务端文本回执，初始等待窗口到期后只能主动查询晚到回执。

## Goals

- 核对同一门店、商品规格和已加购数量，合上规格弹层后再检查自提结算，恢复时避免重复加购。
- 用实屏结算地址和分店名核对高德目的地。只有 SDK 确认 GPS 导航后才反馈导航已启动。转向和距离继续走骑士现有车载 BLE 通道。
- 结算播报包括门店、品项、规格、已核对金额及待付款。分开报告未到结算、定位未就绪、路线未核实及 GPS 启动失败等情况。
- 验证延迟到达的回执是否能用当前对话音色主动播放。测试应可用文本及数据确认，不触发扬声器。

## Confirmed Behavior

- 小布播报已经核实的结算回执。用户明确说「开始导航」后启动，普通确认只记录已听到回执。
- 导航请求使用独立租约，手机只有收到高德 GPS 启动回调才报告启动成功。连接和定位失败给出明确反馈。
- 同一对话的回执等待上限为 55 秒。超过窗口的回执已保留，可用「播报我的自提结果」或「查询导航状态」取回。
