# Knight HUD · AI 适配协议 v2

> 目标：让 ESP32-S3 硬件板（128×64 OLED + 蜂鸣器 + BOOT 键）成为「骑士 App」AI 语音对话与语音控屏的物理显示端。
> 现有 v1（ASCII 文本页）继续兼容；v2 增加中文、状态机、分片、按键回传。

## 0. 链路

```
骑士 App（Web / iOS）                Mac（可选本机 AI 服务）
   │  Web Bluetooth / CoreBluetooth        ▲
   │  BLE (NUS: 6e400001…)                 │ HTTP
   └──────────► ESP32-S3 HUD ◄─── server/knight_hud.py（BLE 客户端，调试/绕过手机用）
                  128×64 OLED + 蜂鸣器 + BOOT 键
```

- 设备名：`ROADLINK-HUD`（兼容旧工具链，不改名）
- 服务/特征值与 Nordic UART 相同：
  - Service `6e400001-b5a3-f393-e0a9-e50e24dcca9e`
  - RX（手机写）`6e400002-…`
  - TX（板子通知）`6e400003-…`
- 编码：**UTF-8**，一条逻辑消息不超过 240 字节。

## 1. 分片（长中文必须分片）

BLE 默认 MTU 净荷 20 字节，一句中文很轻松就超，所以所有消息都可以分片：

```
#<seq>,<fragment>       普通分片，seq 是两位十六进制 00–1f
#<seq>!,<fragment>      最后一片（'!' 表示结束）
```

- 每片 `fragment` ≤ 16 字节，**按字节切**，允许切断 UTF-8 字符（板子重组后再解码）。
- 发送方按顺序写，片间隔 ≥ 10 ms；板子收到最后一片后整体解析。
- 单条逻辑消息 ≤ 240 字节；超长自动截断（板子串口会打印 `[x] overflow`）。
- 短消息（≤ 16 字节 UTF-8）可以不分片，直接发原文。

## 2. App → 板子（显示指令）

| 指令 | 含义 | 示例 |
|---|---|---|
| `S:<state>` | 切屏幕状态 `idle/listen/think/say/act/gate/hud` | `S:listen` |
| `Q:<text>` | 用户说的话（顶部小字，≤ 24 字） | `Q:回复老王：二十分钟到` |
| `A:<text>` | AI 的回答（自动换行+翻页，≤ 120 字） | `A:二十分钟到，已填入微信输入框，要发送吗？` |
| `T:<text>` | 操作卡标题（≤ 12 字，自动切到 act 屏） | `T:微信回复老王` |
| `K:<i>,<n>,<text>` | 第 i/n 步（1 起；每步 ≤ 16 字） | `K:2,4,找到联系人「老王」` |
| `G:<text>\|<yes>` | 请求确认；板子倒计时（默认 8 s），按 BOOT=确认 | `G:发给老王？\|确认发送` |
| `D:<l1>\|<l2>` | 双行 HUD 镜像（对应 App 里 prism3d.setHud） | `D:✓ 已回复\|二十分钟到` |
| `E:<text>` | 错误提示（响 2 声低鸣，显示 1.5 s） | `E:蓝牙已断开` |
| `GA:1` / `GA:0` | App 侧远程点「确认 / 取消」（和板子 BOOT 键等价） | `GA:1` |
| `BEEP` | 蜂鸣自检 | `BEEP` |
| `PING` | 心跳，板子回 `PONG,<毫秒>` | `PING` |
| `DUMP` | 无屏验收：把当前屏幕内容用通知回读（`M/Q/L/K/D1/D2`） | `DUMP` |

说明：
- `S:say` 前先发 `Q:` 再发 `A:`；板子收到 `A:` 自动进入 `say`。
- `K:` 会自动进入 `act` 并高亮当前步；`K:` 全发完 = 操作完成，板子回 `S,act`.
- `G:` 自动进入 `gate`；超时/取消板子通知 `G,0`，确认通知 `G,1`。
- `D:` 自动进入 `hud`，`line1` / `line2` 各 ≤ 8 个汉字（16 px 字体）。

### 兼容 v1（旧 `app/index.html`、`server/hud_push.py`）

`B1/B2/B3`、`DB=87`、`CHK`、`BOOK`、`NEXT`、`BEEP`、`H:<标题>`、`1:…4:<正文>`、`SHOW`、`CLR` 全部保留，行为不变。
注意 `H:` 在 v1 里是「文本页标题」，v2 的双行镜像改用 `D:`，不冲突。

骑行导航沿用 `D:`。例如 `D:右转|67米` 在 2.1 固件显示右转箭头和距离，旧固件显示两行文字。暂停、重算、结束和到达仍使用双行状态文字，蓝牙断开时清除当前提示。

## 3. 板子 → App（通知）

| 通知 | 时机 |
|---|---|
| `V,knight-hud/2.0` | 连接后（由板子主动发一次） |
| `S,<state>` | 状态切换 |
| `B,short` / `B,long` | BOOT 键短按 / 长按（AI 流程里当「说话」/「取消」用） |
| `G,1` / `G,0` | 确认 / 取消（含超时） |
| `S,<build>,<db>,<legal>,<booked>,<screen>` | v1 状态回传（仅旧流程） |
| `PONG,<ms>` | 心跳回复（含开机毫秒数，可看是否重启过） |

## 4. 按键

| 操作 | 空闲 | 确认屏 |
|---|---|---|
| 短按 BOOT | 通知 `B,short`（App 开始录音/说话） | 确认 → `G,1` |
| 长按 ≥ 0.8 s | 通知 `B,long`（App 取消） | 取消 → `G,0` |

## 5. 屏幕状态

| 状态 | 画面 |
|---|---|
| `idle` | 骑士 HUD / 状态行 / `按住 BOOT 说话` |
| `listen` | 「在听…」+ 5 格音量动画 + 「说完松开」 |
| `think` | 「正在思考」+ 转圈点 |
| `say` | 顶部 `Q:` 原文，正文是 `A:` 自动换行；超过 4 行每 3 s 翻页 |
| `act` | 标题 + 4 步清单（✓ 已完成 / ▶ 当前 / ○ 待执行） |
| `gate` | 「需要确认」+ 事项 + 倒计时条 + `BOOT 确认 · 长按取消` |
| `hud` | 双行大字镜像（导航/提醒/结果） |
| `legacy` | v1 的方案/合规/声浪/预约/文本页 |
